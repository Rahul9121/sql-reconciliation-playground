# SQL Reconciliation Playground

I built this as a small, public portfolio piece. It is a static web page where you write and run real SQL in the browser against two deliberately messy synthetic systems: a trade blotter and a ledger. The goal is to practice the same patterns I use when two systems disagree — anti-joins, full outer joins, duplicates, amount breaks with a tolerance, sequence gaps, window functions, NULL handling, CTEs, and top-N per group.

Nothing is uploaded. DuckDB-WASM runs in your browser. The CSVs are fake data generated by a script in this repo.

Live site: https://rahul9121.github.io/sql-reconciliation-playground/

## Why I built it

Reconciliation shows up constantly in data work. Explaining it with slides is weak. I wanted something a hiring manager can open, type SQL into, and feel the problem. I also wanted a project that stays honest: no backend, no keys, no scraped production data, and a test that proves every challenge solution still works.

## How it works

- `index.html`, `css/`, and `js/app.js` are the site. No bundler.
- `js/app.js` loads DuckDB-WASM (pinned on jsDelivr), creates tables from the CSVs, and runs your SQL.
- `data/challenges.json` holds 12 guided puzzles with scenario, hint, starter SQL, solution SQL, and whether row order matters.
- "Check my answer" runs your SQL and the solution SQL, then compares result sets (with optional numeric tolerance).
- `scripts/generate_data.py` builds the synthetic CSVs.
- `tests/test_challenges.py` loads the same CSVs in Python DuckDB and executes every solution.

## Run locally

```bash
python -m pip install -r requirements.txt
make test
make serve
```

Then open http://localhost:8000

On Windows without make:

```bash
python scripts/generate_data.py
python tests/test_challenges.py
python -m http.server 8000
```

## Add a new challenge

1. Append an object to `data/challenges.json` with `id`, `title`, `difficulty`, `topics`, `scenario`, `hint`, `starter_sql`, `solution_sql`, `order_matters`, and optional `tolerance`.
2. Run `python tests/test_challenges.py` and make sure the new solution passes.
3. Commit the JSON change. The UI picks challenges up from the file; no rebuild step.

## Limitations

- Dataset is small (a few thousand rows). That is intentional for GitHub Pages and fast browser loads.
- Answer checking compares the result grid, not a semantic understanding of SQL. Two different correct queries can still fail if columns are renamed or ordered differently than the solution.
- DuckDB-WASM must download from a CDN on first load. Offline use needs a local server for module loading.
- This is a teaching and portfolio tool, not a production recon platform. No workflow, no approvals, no slowly changing dimensions.
